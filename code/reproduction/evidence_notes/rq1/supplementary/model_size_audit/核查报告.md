## 6. 证据冲突核查（任务三）

### 6.1 287 个严格加载失败 + 3 个 URI 敏感模型（v3 重写）

**宽松加载机制**：ATL `EMFModelFactory` 构造设置 `RECORD_UNKNOWN_FEATURE`、`DEFER_IDREF_RESOLUTION`（`javap` 字节码证实）。287 个文件在 ATL 注入下全部加载并计数；元模型版本一致；无修复步骤；E\* 清单与归档对应（哈希）。

**URI 敏感性（3 个模型：Ant/GPT/SM/0023、0024，STM/0044）**：计数随注入器收到的 URI 形式变化——裸路径 4/9/3，file: URI 11/17/11（两轮复核与本地均复现）。

**原实验环境取证（v3 新增，均在仓库内可查）**：
1. 仓库 100+ 个运行日志全部为 Linux（`/home/user/research/llm_mt_experiment/...`）；`logs/ant2maven_failratio_pilot_core_v2.log` 中 `EMFInjector.inject` 的异常消息显示注入器收到的是**无 scheme 绝对路径**（`Error loading /home/user/research/...`）——与执行器代码 `getAbsolutePath()` 一致。
2. ladder 正式运行 run3 的冻结日志（`research_log/2026-06-02_rq1_ladder_corestyle_run3_freeze/` 及 `2026-06-01_ladder_corestyle_formal_run3/*_Ant2Maven_*.log`）显示生成阶段以仓库根相对路径运行（`results_v3_ladder_corestyle_formal_2026-06-01_run3/gpt/generated_models/Ant2Maven/stm/source_model_0001.xmi`）——同一 Linux 代码库。
3. Windows 盘符路径 `C:\...` 在该注入器栈会被解析出单字母 scheme（复核实测报 `unknown protocol: c`）；v2 报告"Linux 与 Windows 均无 scheme"的说法**不成立，予以撤回**。现有证据表明原实验在 Linux 上运行，Windows 机器只出现在后续 bundle 重算。

1. trace href 形如 `/home/user/research/…/results_v3_ladder_corestyle_formal_2026-06-01_run3/…/. exec_normalized/source_model_0023.xmi#traceid_0001`——**Linux、无 scheme 绝对路径、实际载入 `.exec_normalized` 副本**（`traceid_*` 仅存在于规范化副本）；
2. 三个模型的原始 OUTProject 均为 `{Project, build}` 空壳（306/277/304 字节），**零任务规则触发**——任务在原运行中确实被摘除；
3. trace 规则枚举与裸路径 containment 计数严格相等：0023 = Project+3Target = 4；0024 = Project+3Target+4Property+1TaskDef = 9；0044 = Project+2Target = 3；
4. 本地裸路径 `ATLRunnerMulti` 复跑的 OUTProject/OUTMaven 与原始输出**逐字节一致**（306B/316B）。

**结论**：as-executed 计数 4/9/3 定稿；Ant/GPT/SM = **4/11.31/25**、Ant/GPT/STM = **3/12.25/24**（`review_status=confirmed_by_original_trace`）。file: URI 口径 (7,11.46,25)/(6,12.33,24) 与原始运行事实不符，予以排除。
