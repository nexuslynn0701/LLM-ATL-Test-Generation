You are an expert in Model-Driven Engineering (MDE) and model transformation testing.
Your task is to generate one valid source model for testing an ATL model transformation.

--------------------------------
METAMODELS
--------------------------------
Two metamodels are provided below in order: SOURCE first, TARGET second.

The SOURCE metamodel defines the structure your output must conform to.
The TARGET metamodel is provided only to help you understand the target-side
types and bindings referenced in the ATL transformation.

Do NOT instantiate target metamodel classes.
Do NOT generate a target model.
Do NOT use target-only classes, attributes, references, or namespace prefixes
in the source model.

MODEL TRANSFORMATION (ATL)
--------------------------------
Study this ATL transformation carefully to understand which source structures
trigger which rules. Use this knowledge to design a source model that exercises
as many different transformation rules as possible.

module UML2ER;
create OUT : ER, TM : TMM from IN : SimpleUML;

helper def : trace : TMM!Trace = OclUndefined;

entrypoint rule createTrace()
{
	to
		tr : TMM!Trace( )
	
	do {
		thisModule.trace <- tr;
	}	
}

abstract rule NamedElement{ 
 from s : SimpleUML!NamedElement
 to   t : ER!Element(
 	name <- s.name
	)
}

rule Package extends NamedElement{
  from s: SimpleUML!Package
  to t: ER!ERModel(
        entities <- s.ownedElements 
	),
	-- trace information
	tl : TMM!TraceLink(
		ruleName <- 'Package',
		targetElements <- Sequence{t}
	),
	tl2 : TMM!TraceLink(
		ruleName <- 'NamedElement',
		targetElements <- Sequence{t}
	)
  do {
	-- trace information
	tl.sourceElements <- Sequence{s};
	tl2.sourceElements <- Sequence{s};
	thisModule.trace.traceLinks <- tl;
	thisModule.trace.traceLinks <- tl2;
  }
}

}

abstract rule References extends Property{
  from s: SimpleUML!Property (not s.complexType.oclIsUndefined())
  to t: ER!Reference (

--------------------------------
GENERATION REQUIREMENTS
--------------------------------
The source model must:
1. Conform to the source metamodel.
2. Satisfy all OCL constraints.
3. Exercise as many different ATL rules as possible.
4. Be structurally different from the example source models.
5. Be syntactically valid XMI.
6. Use ONLY classes, attributes, references, and namespace prefixes defined
   in the source metamodel.
7. Never instantiate target metamodel classes.
8. Express attribute values as XMI attributes, not as XML text content nodes.
   CORRECT:   <Entry title="My Title" year="2024"/>
   INCORRECT: <Entry><title>My Title</title></Entry>
9. Containment references may be represented as nested XMI elements when
   required by the source metamodel.

--------------------------------
SOURCE FORMAT NOTES
--------------------------------

IMPORTANT CONSTRAINTS for SimpleUML source models:
0. Root element MUST use the SimpleUml namespace prefix:
   CORRECT:   <SimpleUml:Package xmi:version="2.0" xmlns:xmi="http://www.omg.org/XMI" xmlns:SimpleUml="http://SimpleUML" name="...">
   INCORRECT: <Package xmlns:xmi=...> or <Package name="...">
1. complexType is a REFERENCE attribute, not a nested element:
   CORRECT:   <ownedProperty name="author" complexType="//@ownedElements.1"/>
   INCORRECT: <ownedProperty name="author"><complexType name="Author"/></ownedProperty>
2. superClasses is a REFERENCE list:
   CORRECT:   <ownedElements name="Student" superClasses="//@ownedElements.0 //@ownedElements.1"/>
   INCORRECT: <ownedElements name="Student"><superClasses name="Person"/></ownedElements>
3. All ownedElements are top-level children of the Package root element.
4. Use //@ownedElements.N (0-based index) for all cross-references.
